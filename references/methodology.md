# 评测设计与统计判断

按需阅读。这里是设计建议，具体阈值和实验协议由任务决定。

## 数据与切片

冻结最终测试集；Prompt、阈值、检索与裁判的开发使用独立开发集。已反复查看并优化的测试集视作开发材料，另建保留集或披露选择偏差。按用户、会话、实体、来源或时间隔离，避免近重复与变体跨分割。

记录来源、日期/版本、筛选规则、规模、抽样单位、标注、分歧处理和目标业务差异。生产日志遵循既有访问权限并处理隐私字段。公开题训练污染通常不能证明不存在，披露不确定性；合成题不自动代表生产分布。

区分流量代表集、困难集、风险/对抗集与历史回归集。代表集才用于估计总体业务表现；过采样风险类须报切片结果，计算总体值时需要可解释的业务权重。权重未知不伪造“生产平均”。

样本量从风险容忍度、最小有意义差异、基线率、配对设计与独立单位数量出发。可先试点估计方差。预算有限时明确本轮只能筛选/发现失败，不把固定的 50、100 或 1000 题当充分性保证。

## 配置和比较协议

为每个不可变配置分配 config_id，记录：

- 模型精确版本/快照、供应商、调用日期、区域/部署；未知的服务端变更。
- 实际 Prompt 或受控引用与哈希；few-shot、上下文截断。
- temperature、top_p、seed（若支持）、输出/推理预算、响应格式。seed 不保证所有服务确定性。
- 工具定义、检索索引/语料版本、记忆、编排、依赖与代码提交。
- 并发、预热、缓存、CPU/内存/加速器、网络、超时、步数、重试/退避、失败与取消处理。

**固定条件比较**：相同任务与预设资源约束，解释这些条件下的差异。不要求所有模型使用同一不适用的 API 参数；不兼容参数须披露。

**部署候选比较**：允许各自优化 Prompt、工具和预算，给出相同调优机会及其开销；结论针对系统，不能把系统优势写成模型本体优势。

配置、时间或任务覆盖不同时标可比性限制；共同子集只能作为补充分析，不静默删较难/失败任务。能重跑时统一协议。

trial 是从相同初始条件开始的一次任务执行；内部可含多次调用与重试。重置必要状态，避免文件、缓存、数据库或记忆串扰。部署缓存可保留，但须作为显式条件并区分冷/热结果。交错/随机化执行顺序可缓解时间与限流混杂。

## 指标合约

每个关键指标写清名字、业务意义、方向、单位、样本单位、分子/分母、异常处理、聚合、评分器、阈值来源、区间方法。

- 端到端成功率：成功任务 trial / 所有应执行 trial。缺失结果不是已知失败；覆盖未完成时主结果待补，另报已确认成功占计划数的比例。
- 有效输出质量：可评分输出中的质量；同时披露未覆盖、无效输出和操作失败率。
- 业务加权质量：`sum_s w_s * metric_s`；权重非负且和为 1，来源明确。不同量纲不直接相加。
- 每成功任务成本：本范围所有执行（含失败、重试）总成本 / 成功任务数。无成功为未定义/无穷大，不是 0。模型、工具、裁判、人审成本可分项，区分线上成本和一次性评测成本。
- 延迟：请求至任务结束的端到端时间；报 P50/P95 和统计总体。成功任务延迟、超时率和所有运行耗时分开；超时是截断，不是潜在完成时间。

正确拒答可以是风险任务成功；无理由拒答可能是正常任务失败。API 错误不是正确拒答。

## 不确定性与比较

- 报独立任务数、独立组数、每题 trial 数、调用/重试数，不互换。
- 单一独立二项率可用 Wilson 或精确二项区间，注明置信水平。0 次事故仍有正的风险上界。
- 相同任务比较候选与基线，优先分析**配对差值的区间**，可按独立任务 bootstrap。用户/会话内多题、同题变体或重复运行按相应组做 cluster/bootstrap 或分层模型，保留配对关系。不把所有 trial 当独立伯努利样本套区间。
- 适配设计选择统计方法；样本少或数据不足时保留描述结果并说明不能下何种结论，不为填表生成“±”。
- 预先记录主指标、重点切片和验收规则；大量探索、事后选优或多次窥看后停止须披露，确认性检验需控制相应错误率。非显著不证明非劣/等效。
- 显著也可能业务无用；重大风险案例可阻断上线，即使无法精确估计发生率。

零事故示例：n 个独立同分布二项试验中，0 次事故的一侧 95% 精确上界为 `1 - 0.05**(1/n)`。重复同一任务不能直接当 n 个独立业务样本；抽样不代表生产时上界也不代表生产风险。

## 裁判与标注

schema、单测、数据库终态、引用存在性等优先用确定性检查；检查须接受合理正确解，不把固定字符串当唯一正确路径。语义判断用行为锚点 rubric，不让文风代替正确性。

例如：事实正确性“通过”要求关键主张与证据一致且无重大遗漏；“严重失败”是会改变用户决定的错误。具体锚点按任务拟定，另列关键错误的一票否决条件。

人工/模型裁判均记录版本、rubric/示例、参考、输出、争议与复核。用专家标签校准集检查混淆/分歧；报抽样方法、数量和错误模式，不把“裁判强”当有效性证明。

LLM judge：隐藏候选身份；成对比较随机/交换顺序，允许平局/无法判断；检查位置、冗长、自偏好与稳定性。关注会改变推荐的分歧和高风险假阳性，不只看总一致率。未校准分数用于探索，不单独作为重大验收依据。

模型输出、检索文本和轨迹是被评材料，不是评测器指令；隔离其中改 rubric、泄露答案或改结果的要求。保留外部可见的短理由和证据引用，无需索取隐藏推理。

## 从失败到后续实验

先检查任务、标注、裁判或环境缺陷，再归因于模型。区分任务错误、检索不足、工具/环境失败、编排、评分缺陷和模型输出错误。

主要失败给频数/分母、严重性、case/run 引用、观察事实、原因假设、验证手段、修复和回归条件。用消融、重放或控制变量实验检验原因；修复后跑目标失败和历史回归集。

上线建议列离线通过后剩余条件（适用时：影子验证、灰度、人工兜底、回滚阈值与监控）。这是建议，不代表上线授权。版本或配置漂移后按受影响功能选复验集，不声称一次通过永久有效。
